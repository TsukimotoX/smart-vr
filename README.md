# SmartVR

**SmartVR** - учебный проект доступной системы виртуальной реальности, в которой смартфон используется как VR-шлем (HMD), а самодельные контроллеры на базе ESP32 - для отслеживания ориентации и управления.

Цель проекта - спроектировать связную систему из оборудования, программного обеспечения и локального приложения для настройки устройств. Отдельная часть работы - модель данных: устройства, конфигурации, калибровки и история VR-сессий хранятся в SQLite.

> **Состояние проекта:** прототип в разработке. UML-модель и структура базы данных спроектированы; настольное приложение на Python/PySide6 развивается. Описание ниже разграничивает устройство системы и запланированные возможности — оно не означает, что весь VR-трекинг уже реализован.

## Идея и принцип работы

В обычном VR-комплекте шлем, контроллеры и система отслеживания движения часто поставляются как единое решение. SmartVR исследует возможность собрать более доступный комплект из отдельных компонентов:

- **Смартфон** выступает в роли экрана VR-шлема.
- **Контроллеры ESP32 с инерциальными датчиками (IMU)** считывают вращение и действия пользователя.
- **Приёмник** обеспечивает обмен данными с контроллерами.
- **Настольное приложение** предназначено для настройки устройств и конфигураций, работы с сохранёнными данными и диагностики.

Показания IMU позволяют оценивать **ориентацию** контроллера - вращение по трём осям (**3DoF**). Полное определение положения в пространстве, то есть **6DoF** (три вращения и три перемещения), - отдельная техническая задача. Наличие полей координат в базе данных не означает, что позиционное отслеживание уже работает.

## Из чего состоит проект

| Компонент | Назначение | Технологии |
|---|---|---|
| Контроллеры | Чтение данных IMU и органов управления | ESP32, датчики движения |
| Приёмник | Приём данных от контроллеров | ESP32-семейство; радиосвязь |
| Приложение управления | Интерфейс для работы с VR-комплектом и сохранёнными записями | Python, PySide6 (Qt) |
| Локальное хранилище | Конфигурации, параметры устройств, история сессий и диагностические данные | SQLite |
| Модель предметной области | Описание сущностей и их связей | UML |

## Данные и конфигурации

Один VR-комплект может включать смартфон, левый и правый контроллер, а также приёмник. В SmartVR предусмотрено разделение между **физическим устройством** (`Device`) и его **ролью в определённой конфигурации** (`SetupDevice`). Поэтому одно устройство можно использовать в нескольких комплектах без дублирования его характеристик.

Модель SQLite содержит восемь основных сущностей:

| Сущность | Для чего нужна |
|---|---|
| `Device` | Сведения об устройствах |
| `VRSetup` | Сохранённые конфигурации VR-комплекта |
| `SetupDevice` | Устройства в конфигурации, их роли и активность |
| `RadioPairing` | Сопряжения контроллеров с приёмниками |
| `Calibration` | Результаты калибровок |
| `Session` | История запусков VR-комплекта |
| `Telemetry` | Сохранённые показания датчиков |
| `InputEvent` | События органов управления |

**Пример:** при запуске конфигурации создаётся запись `Session`. Во время работы система *может* сохранять измерения в `Telemetry` и нажатия кнопок в `InputEvent`. Каждая такая запись относится к конкретным сессии и устройству.

### Обработка данных и их хранение

Для управления в реальном времени показания датчиков необходимо обрабатывать по мере поступления, в оперативной памяти. Постоянная запись каждого измерения в SQLite не требуется для работы VR и быстро увеличивала бы размер базы.

Предполагаемая политика хранения:

- события кнопок записывать при **изменении состояния**, а не каждый кадр;
- телеметрию сохранять **выборочно, в диагностическом режиме**;
- частоту логирования и сроки хранения определить отдельно при реализации.

Таким образом, **частота получения данных от IMU** и **частота их записи в базу** — разные параметры. Точные частоты пока не закреплены в архитектурной документации.

## Предметная область и UML

Модель данных получена из описания предметной области: выделены основные объекты системы, их характеристики и отношения между ними. Для учебного анализа использован **метод Аббота** — существительные в описании рассматриваются как кандидаты в сущности или атрибуты, а глаголы помогают определить связи и операции.

Полное описание предметной области, таблица выделенных понятий и обоснование связей находятся в **[domain-analysis.md](domain-analysis.md)**.

## Технологии

- **Python / PySide6 (Qt)** — настольный графический интерфейс.
- **SQLite** — локальная реляционная база данных.
- **ESP32** — аппаратная основа контроллеров и приёмника.
- **UML** — проектирование структуры данных и связей.

## Текущее состояние и развитие

**Подготовлено в учебной части:** описание предметной области, UML-модель, схема хранения данных и демонстрационные записи SQLite.

**В разработке:** настольный интерфейс и операции управления сохранёнными данными; прошивки устройств и интеграция аппаратной части.

**Дальнейшие направления:** проверка передачи данных от контроллеров, калибровка, обработка ориентации, режим диагностики и контролируемое хранение истории. Позиционное отслеживание 6DoF требует отдельного решения.
